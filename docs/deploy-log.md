### 서버 여력 점검 (배포 전)

씽크와이즈와 NAS가 이미 도는 PC라 자리가 있는지 먼저 확인했다.

- RAM 15.8GB 중 6.6GB 여유, **커밋 차지 11.1/17.3GB** — 스왑 압박 없음(이 숫자가 실제 판단 근거)
- CPU 부하 9% (Pentium G7400, 2코어)
- 8000번 포트 비어 있음, C: 128GB 여유

메모리 상위 목록에 씽크와이즈도 NAS도 안 보였고 제일 무거운 건 Edge(3개 합쳐 885MB)였다.
uvicorn 하나(70~120MB)는 Edge 탭 하나보다 가볍다고 판단해 진행했다.
**코어가 2개뿐이라 `--workers`는 늘리지 않았다.**

### 겪은 문제 3건

**1. `.ps1` 실행이 막힘 (`UnauthorizedAccess`)**

윈도우가 직접 만든 스크립트 파일의 실행을 기본 차단한다.
`PowerShell -ExecutionPolicy Bypass -File .\스크립트.ps1` 형태로 **이번 실행에만** 예외를 뒀다.
`Set-ExecutionPolicy`로 정책 자체를 풀지는 않았다 — 씽크와이즈와 NAS가 도는 PC의 전역 보안 설정을
이 앱 하나 때문에 낮출 이유가 없다.

**2. 서버가 뜨자마자 죽음** (수정: `8ce9c3e`)

`run_server.ps1` 첫머리의 `$ErrorActionPreference = "Stop"`이 원인이었다.
uvicorn은 `INFO: Started server process` 같은 **정상 로그도 표준 오류(stderr)로 내보내는데**,
파워셸은 외부 프로그램이 stderr에 쓰면 그것을 오류로 포장한다.
`Stop`이 그 포장을 중단 사유로 삼아서 **"서버가 시작됐습니다"라는 성공 알림이 서버를 죽였다.**

수정은 설치 검사(`.venv`·`.env` 존재를 보는 `throw` 두 줄)가 끝난 **뒤에** `Continue`로 되돌리는 것.
검사가 위쪽에 있고 `throw`는 이 설정과 무관하게 중단시키므로, **설정 실수는 여전히 시끄럽게 죽고
정상 로그만 조용히 지나간다.** 로그에 남길 때는 `"$_"`로 오류 포장을 벗겨 원래 한 줄만 남긴다.

**3. 로그의 한글이 `?쒖옉`으로 깨짐** (수정: `bdad922`)

처음엔 파이썬 출력 인코딩(`PYTHONIOENCODING`)을 의심했는데 틀렸다.
진짜 원인은 **스크립트 파일 자체**였다 — 윈도우 PowerShell 5.1은 `.ps1`을 열 때 파일 맨 앞
3바이트 표식(BOM)이 없으면 UTF-8이 아니라 시스템 기본 글자표(cp949)로 읽는다.
그래서 스크립트 안의 한글이 **파싱 시점에 이미 깨진 채로** 변수에 들어갔고,
그 깨진 글자가 로그에 *정확하게* 저장됐다. 읽을 때 `-Encoding UTF8`을 붙여도 안 고쳐지던 이유다.

`.ps1` 세 개를 BOM 붙여 다시 저장해 해결했다.
**실질 피해는 로그 헤더가 아니라 `throw` 메시지였다** — `.venv`가 없을 때 뜨는 안내가
전부 깨진 채로 나오게 돼 있었다. 평소엔 안 보이다가 사고 났을 때만 드러나는 자리에 있던 병이다.

### 결정과 이유

**설치 위치를 `C:\apps`로.** 작업 스케줄러가 SYSTEM 계정으로 실행하는데 `C:\Users\...` 아래에 두면
권한이 얽히기 쉽다. (실제로는 SYSTEM이 사용자 폴더의 파이썬을 문제없이 읽었지만, 여지를 남길 이유가 없다.)

**개인용/서버용 실행 파일을 분리.** `run_local.ps1`은 `127.0.0.1`, `run_server.ps1`은 `0.0.0.0`.
한 파일에 옵션으로 두면 개인 PC에서 무심코 사내에 열리는 사고가 난다.

**IP를 고정하지 않고 컴퓨터 이름으로 안내.** 서버 IP가 공유기 자동 할당(DHCP)이라 언젠가 바뀔 수 있다.
공유기에 고정 예약을 넣는 방법도 있었지만, 일부 공유기는 설정 저장 시 재시작해서 **사내망 전체가
잠깐 끊긴다.** `DESKTOP-318VJ68:8000`이 실제로 되는 걸 확인했고, 이러면 IP가 바뀌어도 링크가 따라가고
공유기를 한 글자도 안 건드린다. 윈도우 PC끼리 이름을 찾는 기능에 기대므로 100%는 아니다 —
안 되는 PC가 나오면 그 PC에만 IP를 알려주면 된다.

**로그인은 보류.** 본인 판단으로 미뤘다. 현재 접근 제한은 방화벽의 대역 제한뿐이다.

### 검증한 것 / 안 한 것

확인함 — 다른 PC에서 검색 성공, 방화벽 통과, 이름 접속, 서버 프로세스 상시 대기,
씽크와이즈 관련 기존 작업을 덮어쓰지 않음(`ThinkwiseWiki` 외에 같은 이름 없음).

**확인 안 함** — ①**재부팅 후 자동 시작.** 등록만 확인했고 실제로 재부팅해보지는 않았다.
씽크와이즈가 도는 서버라 확인 목적으로 재부팅하지 않았고, 다음 재부팅 때 보기로 했다.
②**여러 명 동시 검색 시 DB 부하.** 지금까지 검색은 전부 한 명이었다.

### 남은 일

1. **공지는 단계적으로.** 이 앱은 씽크와이즈와 같은 MySQL에 붙고, 검색이 `LIKE '%검색어%'`라
   테이블을 통째로 훑을 수 있다. 여러 명이 동시에 검색하면 **씽크와이즈 본체가 느려진다.**
   소수에게 먼저 열어 며칠 관찰하고, 이상 없으면 전체 공지한다.
   문제가 생기면 `Stop-ScheduledTask -TaskName ThinkwiseWiki` 한 줄로 내린다.
   (데이터가 망가질 위험은 없다 — `tw_ro`는 `SELECT`만 가능하다.)
2. **로그인 붙이기.** 사람이 늘기 전에.
3. 검색이 느려지면 읽기 복제본이나 별도 검색 인덱스 검토.
