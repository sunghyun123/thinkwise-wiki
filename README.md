# 씽크와이즈 위키

씽크와이즈의 작업 이력을 검색하는 **읽기 전용** 사내 도구입니다.

## 어떻게 동작하나

검색할 때마다 운영 DB를 조회하지 않습니다. `work_log`를 **로컬 SQLite 색인으로 복제해 두고 거기서만 검색**합니다.

```
운영 MariaDB  ──(10분마다 증분 복제: indx > 커서)──▶  data/wiki_index.db  ──▶  검색
```

이렇게 한 이유는 실측 때문입니다. 검색어가 `LIKE '%…%'`라 인덱스를 못 타고, `work_log`에는
`c_date` 인덱스조차 없어서 **검색 한 번마다 53만행 전체 스캔 + 정렬**이 일어났습니다.

| | 운영 MariaDB 직접 조회 | 로컬 색인 |
| --- | --- | --- |
| `'공사'` 검색 | 663ms | **304ms** |
| 100건 → 1000건 | 비용 동일(어차피 전량 스캔) | **+14ms** |
| 운영 DB 부하 | 매 검색 전체 스캔 | **없음** |

증분 복제는 `indx`(PK) 범위 스캔이라 **지금까지의 검색 1회보다도 가볍습니다.**
근거: 53만행에서 `indx` 순서와 `c_date` 순서의 역전이 0건이라 `indx`를 커서로 쓸 수 있습니다.

## 검색 결과의 단위 — 이벤트가 아니라 가지

`work_log`는 이벤트 로그라 가지 하나에 ADD·EDIT·MOVE·PASTE·DEL이 전부 남습니다.
그대로 보여주면 같은 내용이 여러 줄로 반복되므로, **(맵 + 내용)이 같은 기록을 한 줄로 접어서** 보여줍니다.

- 접기는 저장하지 않고 **검색할 때 계산**합니다. 저장하면 새 이벤트가 들어올 때마다 요약을
  갱신해야 하고, 갱신 경로를 하나만 빠뜨려도 영구히 어긋납니다.
- 그래서 **펼치기**로 원본 기록을 그대로 볼 수 있습니다(운영 DB를 다시 부르지 않음).
- **삭제된 가지는 검색되지 않습니다**(전체 가지 286,538개 중 20,881개 = 7.3%).
  잘못 쓴 것이나 남에게 보이기 싫어 지운 것이 계속 조회되면 지우는 행위에 효과가 없고,
  그러면 마음 놓고 쓰지 못합니다. 검색 목록과 펼치기 **양쪽**에서 가립니다.
  색인에는 원본 기록을 그대로 두고 내보내는 지점에서만 가리므로, 정책을 바꿀 때
  53만행 재적재가 필요 없습니다.
  - **한계:** 가지 제목이 바뀐 뒤 지워진 경우, **옛 제목으로 접힌 줄은 남습니다.**
    가지의 신원이 (맵 + 제목)뿐이라 옛 제목과 새 제목을 연결할 방법이 색인에 없습니다.
- 씽크와이즈는 가지를 옮길 때 `MOVE` 뒤에 `DEL`을 함께 남깁니다(전체 MOVE의 88%).
  이걸 삭제로 세면 멀쩡한 가지 **18,197개가 검색에서 통째로 사라지므로**, 적재할 때 표시해 두고 제외합니다.
- 흔한 검색어는 결과가 수만 건이라(`'공사'` = 23,139개 가지) **연도·맵·작성자 필터**로 좁힙니다.
  잘린 경우 몇 개가 안 보이는지 화면에 적습니다.

## 현재 범위

- 접속 범위는 실행 방식으로 갈립니다. 개인 PC에서 `run_local.ps1`로 띄우면 `127.0.0.1`(그 PC 전용),
  사내 서버에서 `run_server.ps1`로 띄우면 `0.0.0.0`(사내망 공개)입니다. [사내 배포 절차](docs/deploy-windows.md)를 참고하세요.
- **로그인이 없습니다.** 사내 공개 시 URL을 아는 사람은 누구나 검색할 수 있으며, 접근 제한은 방화벽의 대역 제한뿐입니다.
- 검색어는 공백을 제외하고 최소 2글자, 최대 100글자입니다.
- 한 번에 50/100/200/500건을 선택하며 서버 상한은 500건입니다.
- 입력할 때마다 자동 검색하지 않고 검색 버튼을 눌렀을 때만 조회합니다.
- SQL은 파라미터 바인딩을 사용해 검색어를 쿼리에 직접 결합하지 않습니다.
- 운영 DB에 나가는 SQL은 **동기화가 실행하는 두 개의 `SELECT`뿐**입니다.
  - `tw_colla_log.work_log` (증분: `WHERE indx > ?`)
  - `tw_colman.collaboration_board` (87행 전량)

> 중요한 안전 조건: 앱 코드가 읽기 전용이어도 DB 계정에 쓰기 권한이 있으면 운영 안전을 보장할 수 없습니다. 반드시 두 테이블에 대한 `SELECT` 권한만 가진 전용 계정을 사용하세요.

## 알려진 데이터 한계

운영 데이터 자체의 성질이라 앱에서 고칠 수 없는 것들입니다.

- **작성자가 빈 기록이 12.1%**(65,357행)입니다. 접힌 줄에는 *이름이 남은 가장 최근* 기록의 작성자를
  보여주지만, 그런 기록이 하나도 없으면 빈칸입니다.
- **맵 이름을 못 찾는 행이 32.7%**입니다. 로그에는 협업 168개가 등장하는데
  `collaboration_board`에는 87개만 남아 있습니다(지워진 협업으로 보입니다).
- 맵 이름이 사람 이름인 경우가 많습니다(개인 업무 맵). "맵"과 "수정한 사람"에 같은 이름이 나올 수 있습니다.
- `detail`이 `'|'` 하나뿐인 행이 4.5%, 3글자 이하가 15.7%입니다.

## 최초 설치 (Windows PowerShell)

Python 3.11 이상이 설치된 환경을 권장합니다. 아래 명령은 이 프로젝트 폴더에서 실행합니다.

```powershell
$python = "$env:LOCALAPPDATA\Programs\Python\Python311\python.exe"
& $python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env`를 메모장으로 열어 실제 MariaDB 접속 정보를 입력합니다.

```dotenv
DB_HOST=MariaDB서버주소
DB_PORT=3306
DB_USER=thinkwise_wiki_reader
DB_PASSWORD=전용계정비밀번호
DB_CONNECT_TIMEOUT=5
DB_READ_TIMEOUT=10
```

DB 전용 계정이 없다면 DBA에게 [docs/readonly-account.sql.example](docs/readonly-account.sql.example)을 전달하세요. 앱이 실행하는 파일이 아니며, DBA가 접속 허용 호스트와 비밀번호를 실제 값으로 바꿔 수동 적용하는 예시입니다.

## 검색 색인 만들기

앱은 로컬 색인에서만 검색하므로, **색인을 먼저 만들어야 검색이 됩니다.**

```powershell
PowerShell -ExecutionPolicy Bypass -File .\sync_index.ps1 -Full
```

53만행 기준 약 20초, 색인 파일은 105MB 정도이며 `data\wiki_index.db`에 생깁니다(저장소에는 올라가지 않습니다).
이후에는 `-Full` 없이 실행하면 새로 생긴 것만 가져옵니다. 사내 서버는 작업 스케줄러로 자동화합니다
([배포 절차](docs/deploy-windows.md) 참고).

색인이 없으면 검색이 "결과 0건"이 아니라 **503으로 실패**합니다. 아직 준비가 안 된 것과
정말 결과가 없는 것은 다른 상황이라 구분해서 알립니다.

## 실행

PowerShell에서 다음을 실행합니다.

```powershell
.\run_local.ps1
```

브라우저에서 <http://127.0.0.1:8000>을 엽니다. 종료할 때는 실행 중인 PowerShell 창에서 `Ctrl+C`를 누릅니다.

`run_local.ps1`에는 `--host 127.0.0.1`이 고정되어 있습니다. **이 파일은 개인 PC 전용이므로 여기를 `0.0.0.0`으로 바꾸지 마세요.**
사내에 공개할 때는 이 파일을 고치는 게 아니라 `run_server.ps1`을 씁니다. 두 실행 방식을 파일로 갈라 두어야
개인 PC에서 무심코 사내에 열리는 일이 생기지 않습니다.

## 사내 서버 구동

씽크와이즈 DB가 있는 PC에서 상시 구동해 사내 전체에 공개하는 절차는 [docs/deploy-windows.md](docs/deploy-windows.md)에 있습니다.
`run_server.ps1`(0.0.0.0 구동 + 파일 로그)과 `install_task.ps1`(재부팅 시 자동 시작 등록)을 사용합니다.

사내 접속 주소는 <http://wiki.yjselect.com:8000>, 예비 주소는 <http://DESKTOP-318VJ68:8000> 입니다.

주소가 둘인 이유는 각자 다른 일을 하기 때문입니다. **도메인 쪽은 메신저에 링크로 보내기 위한 것**입니다.
카카오톡 같은 메신저는 점과 최상위도메인(`.com`)이 있어야 주소로 인식하므로, 윈도우 컴퓨터 이름인
`DESKTOP-318VJ68`은 링크가 되지 않고 글자로 전달됩니다. **컴퓨터 이름 쪽은 IP가 바뀌어도 따라가는 것**이 장점입니다.

**주소는 세 부분이 다 맞아야 하고, 어긋나면 셋 다 다르게 실패합니다.**

| 어긋난 것 | 실제로 일어나는 일 |
| --- | --- |
| `:8000` 누락 | 80번은 **씽크와이즈 본체(IIS)**입니다. 에러가 아니라 씽크와이즈 협업플랫폼 로그인 화면이 정상적으로 뜹니다. |
| `https://` 사용 | 연결 실패. 이 서버는 평문 http만 서비스합니다. |
| 컴퓨터 이름 사용 | 접속은 되지만 메신저가 링크로 잡지 않습니다. |

**ERP 도메인(`yjsboard.com`)의 서브도메인은 쓸 수 없습니다.** 그 도메인이 `includeSubDomains`가 붙은 HSTS 헤더를
보내고 있어서, 브라우저가 그 아래 모든 주소를 요청 내보내기 전에 https로 바꿔버립니다. `yjselect.com`은 같은 헤더를
보내되 `includeSubDomains`가 없어 서브도메인이 자유롭습니다.

도메인은 A 레코드에 IP(`192.168.0.76`)를 직접 적어 둔 것이라 그 PC의 IP가 바뀌면 죽습니다.
**컴퓨터 이름으로는 되는데 도메인으로 안 되면 IP가 바뀐 것**이고, `yjselect.com` DNS에서
`wiki` A 레코드의 값만 새 IP로 고치면 복구됩니다.

## 동작 확인

개발용 의존성을 설치하고 자동 테스트를 실행합니다. 테스트는 실제 MariaDB에 접속하지 않습니다.

```powershell
& .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
& .\.venv\Scripts\python.exe -m pytest
```

실제 DB 연결 확인은 앱을 실행한 뒤 두 글자 이상의 검색어로 한 번 조회하는 방식으로 진행합니다. 연결 정보나 DB 오류 원문은 브라우저에 노출하지 않습니다.

## DB 부하 관련 메모

**검색은 더 이상 운영 DB를 건드리지 않습니다.** 사람이 몇 명 늘어도 운영 DB에 가는 부하는
10분마다 한 번 도는 증분 복제뿐이고, 그건 `indx` PK 범위 스캔이라 매우 가볍습니다.

운영 DB에는 여전히 인덱스 추가나 테이블 변경을 하지 않습니다. 색인 방식을 고를 때
SQLite FTS5(trigram)도 검토했지만 **쓰지 않기로 했습니다** — trigram은 3글자 이상만 처리해서
`공사·설계·견적·도면` 같은 2글자 검색이 전부 0건이 됩니다. 로컬에서는 평범한 `LIKE` 전체 스캔이
25~300ms라 색인 기술이 필요하지 않았습니다.

## 파일 구성

```text
app/
  main.py              FastAPI 라우팅과 오류 처리
  config.py            .env 설정 로딩
  index_db.py          로컬 SQLite 색인의 스키마와 연결
  sync.py              운영 MariaDB -> 로컬 색인 증분 복제
  search_index.py      로컬 색인 검색 (접기·필터·펼치기)
  models.py            API 응답 형식
  static/index.html    단일 HTML/CSS/바닐라 JS 화면
data/
  wiki_index.db        검색 색인 (저장소에 없음, sync_index.ps1로 생성)
docs/
  readonly-account.sql.example
  deploy-windows.md    사내 서버 배포 절차
  deploy-log.md        배포 기록 (무슨 일이 있었고 왜 그렇게 정했나)
tests/
run_local.ps1          개인 PC 실행 (127.0.0.1)
run_server.ps1         사내 서버 실행 (0.0.0.0 + 파일 로그)
sync_index.ps1         색인 동기화 (-Full 이면 처음부터 다시)
install_task.ps1       웹 서버 자동 시작 등록 (관리자 권한, 1회)
install_sync_task.ps1  색인 동기화 주기 실행 등록 (관리자 권한, 1회)
requirements.txt
```

## API

| 경로 | 설명 |
| --- | --- |
| `GET /api/search?q=&limit=&year=&map=&author=` | 접힌 검색 결과 + 필터 선택지 + 색인 갱신 상태 |
| `GET /api/branch/{branch_id}` | 접힌 한 줄을 펼쳐 원본 기록 보기(최근 300개) |
| `GET /api/status` | 색인이 얼마나 낡았는지 |
